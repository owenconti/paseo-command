# DOM Atlas Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A second Atlas renderer built from DOM, SVG and CSS, served at `/dom`. It draws the same fleet as the Phaser Atlas with the same art and rules, at clearly lower CPU/GPU cost.

**Architecture:**
- First, the Phaser Atlas's renderer-neutral parts move into shared modules: painters that return canvases, plus perimeter, camera, placement, ribbon and pick geometry. Both renderers call them.
- The DOM renderer puts every static picture into one world element whose CSS `transform` is the camera.
- Live state lives in small, separately composited elements, animated with CSS and the Web Animations API on `opacity` and `transform` only.
- A cost spike gates the full port.

**Tech Stack:** TypeScript, Vite 7, React 19 (host app only), Phaser 4.2.1 (existing Atlas, untouched engine), Playwright (headed Chrome) for e2e and measurement, `node --test`.

**Spec:** `docs/superpowers/specs/2026-10-27-dom-atlas-design.md`

## Global Constraints

- Local only. No publishing, no Phaser AE sign-in or streamer. Never reach a real daemon; tests use `mockApi` and the fake daemon only.
- Do not edit `phaser/`, `game/node_modules/`, or `/Users/example/development/paseo-command`.
- Baseline is the Atlas at commit `73df182`. Build on branch `dom-atlas` in a worktree from `73df182`. The uncommitted plaza work in the main checkout (props, lamps, beacon glows) is out of scope. Leave it untouched.
- Galaxy is unchanged. `WORLDS` and `WorldKind` stay `{ atlas, galaxy }`. The toolbar gets no new entry.
- The DOM Atlas lives at `/dom`. Every other path is unchanged.
- Same art, same rules: every rule in `CLAUDE.md` "Atlas world" and "Confirmed map constraints". Labels stay at fixed world scale, with no screen-size compensation.
- Agent states stay distinct with the same colours (`STATE_TILE`) and pulse periods (failed 1200 ms, approval 1800, question 1800, done 3200, running light 2200).
- Reduced motion (`prefers-reduced-motion` or `motion(true)`): everything still, selection wash steady at the `t = 0.5` pose.
- No per-frame JS in the DOM renderer at rest. `requestAnimationFrame` is allowed only while a camera transition or gesture is in progress.
- No animated CSS or SVG filters. Blur is computed once.
- Success: a clear CPU/GPU drop measured in headed Chrome on the Mac. My call for "clear": the DOM figures are ≤ 70% of Phaser's (renderer + GPU process CPU %) in both the idle and the pan/zoom runs on the large fleet.

## Review Focus

1. **Resizing the map pane** (window resize, panel open or close). The DOM world must re-lay out by aspect, refit if the old camera is no longer valid, and keep picking aligned. Pinned in Task 6 (`resizing keeps picks aligned`).
2. **Live fleet updates while the camera is mid-pan or a robot is mid-walk.** The camera stays put, walkers keep their place, and only changed tiles restyle. Pinned in Task 7 (`live state change restyles one tile and keeps the camera`).
3. **A selected entity that disappears in an update.** The selection clears quietly with no stale halo, as Phaser does. Pinned in Task 6 (`vanished selection clears`).
4. **Hosts on the map.** Never hover or pick from land or banner. A host selected from the Hosts tab rings its whole landmass with no wash. Pinned in Task 6 (`hosts are not interactive; host selection rings landmass without wash`).
5. **Tab hidden or reduced motion toggled at runtime.** Animations stop, poses go still, and no JS timers keep running. Pinned in Task 7 (`reduced motion stops every animation`).

### Task 6: Static world, camera and input

**Files:**
- Create: `rendering/src/dom/assets.ts`, `rendering/src/dom/sea.ts`, `rendering/src/dom/land.ts`, `rendering/src/dom/view.ts`
- Modify: `rendering/src/dom/DomAtlas.ts`, `rendering/src/dom/atlas.css`
- Test: `web/e2e/atlas-dom.e2e.ts`

**Interfaces:**
- `assets.ts`:
  - `loadArt(): Promise<{ frames: Map<string, Frame & { url: string }>; sand: HTMLImageElement }>`. It loads the four PNGs, calls `buildFrames`, and gives each frame a blob URL through `canvas.toBlob`. It is cached for the page's life.
  - A load failure emits `error("Could not load <name>. Reload the world to retry.")`.
  - `bakeTint(canvas, tint: number, alpha: number): HTMLCanvasElement` copies the canvas, fills it with `multiply` using the tint, and restores alpha with `destination-in`. This matches Phaser's multiplicative tint.
- `view.ts`:
  - `class View { constructor(viewport: HTMLElement, world: HTMLElement, onChange: () => void); centerX; centerY; zoom; size(): ViewSize; worldView(): Box; toWorld(cssX, cssY): P; toScreen(x, y): P; set(c); pan(x, y, ms); zoomTo(level, ms); fit(layout) }`.
  - Zoom uses the same render-px units as `camera.ts`, with density 2. The CSS scale is `zoom / 2`.
  - Transitions use `requestAnimationFrame` with cubic ease-out over 380 ms, and only while running.
  - Every `set` goes through `clampCamera`.
- `land.ts`: `buildLand(world: HTMLElement, layout, art): void`.
  - One terrain element per `Piece`, with offline pieces baked through `bakeTint`.
  - Structures from `placeStructures` as `<img>`, with `flipX` as `scaleX(-1)`.
  - Camp flags as a small inline SVG.
  - Banners from `labels` plus `ribbonShape` as an absolutely positioned SVG and a text `<div>`. Fonts come from `ribbonFont`, and `fitCaption` measures with a canvas 2D context in the same font.
- `sea.ts`: `buildSea(world: HTMLElement, layout): void`.
  - Three repeating-background layers sized to `mapExtent` plus one tile of margin, stacked water → glints → (variation from terrain) → landmass.
  - Clouds sit above the structures and below labels and robots.
- DOM stacking inside the world element, bottom to top:
  1. Water, glints, variation and landmass.
  2. Islands.
  3. The state layer, then hover, then the selection wash and rim.
  4. Structures.
  5. Clouds.
  6. Banners.
  7. Robots and drones.

  Each group is its own element in that order; no `z-index` juggling inside groups.

**Values fixed by today's code:**
- Glints use the 512 px tile at scale 1.6 (819.2 world px) and α 0.7. They drift by `(-0.0018, +0.00075)` world px/ms, looped every 5,461,333 ms (12 tiles × 5 tiles), with `steps(81920)` (15 Hz).
- Clouds use the 512 px tile at scale 6 (3072 world px) and α 0.2. They drift by `(+0.003, +0.0012)` px/ms, looped every 5,120,000 ms (5 × 2 tiles), with `steps(76800)`.
- The water colour behind everything is `WATER`.

**Input:**
- Drag pans.
- Wheel zooms around the pointer by `exp(-dy * 0.001)`.
- Arrow keys pan at 0.65 render px/ms while held, with `requestAnimationFrame` only while a key is down.
- `F` and `Home` fit. `Escape` emits `pick(null)`.
- A click within 7 px of the press picks through `entityAt`.
- Hover uses `entityAt` on `pointermove` (throttled to one per animation frame) and is cleared on drag, wheel and leave.
- Keys belong to the parent element only.
- While the camera moves, add `will-change: transform` to the world element. Remove it 200 ms after the camera stops, so text and SVG re-rasterise crisply.

### Task 7: Live layer: state hexes, hover, selection, robots and drones

**Files:**
- Create: `rendering/src/dom/live.ts`, `rendering/src/dom/robots.ts`
- Modify: `rendering/src/dom/DomAtlas.ts`, `rendering/src/dom/atlas.css`
- Test: `web/e2e/atlas-dom.e2e.ts`

**Interfaces:**
- `live.ts`:
  - `class Live { constructor(layers: { state: HTMLElement; hover: HTMLElement; selection: HTMLElement }); tiles(layout): void; hover(entity | null, cells: Axial[]): void; select(entity | null, cells: Axial[]): void; reduced(on: boolean): void }`.
  - `tiles` is keyed by agent id and only restyles tiles whose state changed.
- `robots.ts`: `class Robots { constructor(layer: HTMLElement, art); sync(layout): void; reduced(on: boolean): void; destroy(): void }`. Walkers keep their position across `sync` calls.

**Each state tile:**
- It is its own absolutely positioned element at the cell, so `opacity` and `transform` animations composite on their own.
- Fill: `STATE_TILE` colour at α 0.42 (0.25 offline) on a `HEX_RADIUS − 1` hex.
- Inner line: `#fff8e6` at α 0.7, 1.5 px, at `HEX_RADIUS − 10.5`.
- Border: 9 px at `HEX_RADIUS − 5.5`, α 0.95 (0.6 offline).
- Pulsing states animate border `opacity` between 0.35 and 1 with a cosine-like `ease-in-out` alternate keyframe over each state's period.
- Running tiles carry the light technique chosen in Task 5.
- Phase: a negative `animation-delay` of `random(seedOf(id + "pulse"))() * period`.

**Selection and hover:**
- Selection: the wash is the cells' hexes at `HEX_RADIUS + 0.5`, filled `#ffe27a`, with `opacity` breathing between 0.10 and 0.26 over 1600 ms.
- The rim is `perimeter(cells, 6)` stroked `#ffc72e` with round caps.
- The halo is the same path stroked wider (18 px), with a fixed `feGaussianBlur stdDeviation 6`, in its own `<svg>` element whose `opacity` breathes in step with the wash. It is never a live filter.
- Hosts get no wash.
- Hover is `perimeter(cells, 4)` in `HOVER_COLOR[kind]`.

**Robots:**
- Each robot is a wrapper element at its cell holding body and hands `<img>`s at `ROBOT_SIZE`, tinted `#9c9a92` with α 0.7 when offline (baked through `bakeTint`).
- Walking: when a busy robot's leg ends, pick the next target with its seeded rng (`seedOf(id + "walk")`), using the same rules as `walkRobots` and `wander.ts` constants. Then run one Web Animation of `transform` that turns at `TURN_SPEED`, walks at `WALK_SPEED` with the 1.8 px bob, and holds a pause of 1200–3600 ms. JS runs only on `finish`.
- Hands swing or tinker with CSS keyframes.
- Drones orbit with a keyframed `translate` around an ellipse of 40×28, lift 18 ± 2, over `DRONE_ORBIT`. Each has a phase, a shadow ellipse and up to 4 drones.
- Far-side depth is the builder's choice of technique, as long as it looks the same.

**Reduced motion:** a `.reduced` class on the root sets `animation: none`, and every Web Animation is cancelled. Robots return to the centre with heading 0, drones go to their phase-0 pose, and the wash and halo use the `t = 0.5` pose.
